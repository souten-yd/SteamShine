# X52 HOTAS addon

SteamShine's Addons page detects the standard Logitech/Saitek X52 (`06a3:075c` or `06a3:0255`). Settings are editable only while a matching USB device is connected. The **Recommended** profile is present initially and is read-only. It starts disabled so attaching a controller does not overwrite its current display state. Enable the addon while connected to apply it. Create named profiles with **Save and activate**; changes are stored in `steamshine_x52_profiles` in the Sunshine configuration and reapplied after service restart or USB reconnection.

The card shows the connection, addon switch, input switch, and profile actions first. Open **Lighting, display, and button settings** only when changing those controls. **Accept X52 input** starts on and is independent of **Enable addon**. Turning input off exclusively grabs the X52 Linux event device, suppressing joystick events for games and keyboard assignments from this addon. Turning it back on releases the grab. The choice is stored with the profiles and restored after a service restart or USB reconnection. If the input device cannot be opened and grabbed, the API rejects switching input off.

The standard X52 supports shared LED brightness, shared throttle/POV blinking, three 16-character MFD text lines, MFD brightness, the shift indicator, 12/24-hour clock, date order, and offsets for the two extra clocks. The display accepts printable ASCII text. LED colors for individual buttons belong to the X52 Pro and are not offered for a standard X52. The hardware command format follows the [libx52 project's vendor protocol](https://github.com/nirenjan/libx52/blob/master/libx52/commands.h).

Each of the 34 physical buttons can additionally send one keyboard key. The joystick event is still passed to the game. This is useful for games that accept keyboard shortcuts alongside joystick controls. No key is emitted if **Joystick only** is selected. This feature needs access to `/dev/input/event*` and `/dev/uinput`; if the service account lacks access, display controls can still work but assigned keys cannot be emitted. The Linux user session normally grants access to the local desktop user.

The Addons page also shows the last pressed X52 button number so a physical control can be identified before assigning a key. The button labels follow the standard X52 layout; the reported number is the Linux event order used for assignments.

The recommended profile uses moderate LED and MFD brightness, disables blinking and shift, displays a short SteamShine label, uses a 24-hour clock and `YYMMDD`, and leaves every button as joystick only. The Web API authenticates profile updates with the same session and CSRF checks as other Addon settings. A disconnected X52 cannot be enabled or changed through that API.
