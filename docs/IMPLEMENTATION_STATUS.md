| Upstream and SteamShine Web UI coexistence | Implementing | Phase 0 builds the locked upstream Vite frontend as a dependency of the runtime binary, stages generated assets rather than raw EJS/Vue source, and rejects missing bundles, manifest, English locale, unresolved EJS, and unresolved local static assets before archiving. The generated frontend now uses root-relative asset, API, locale, and navigation URLs, fixing route-relative bundle/API 404s that left Vue interpolation visible on `/welcome/` and other non-root pages. Phase 1 adds shared credential, session, pairing, client, status, and diagnostic services plus the `/api/steamshine/v1/` facade. Pairing and client services now share an injectable backend: a fake backend proves PIN success, list visibility, and revoke state in GTest while the production backend remains NVHTTP. SteamShine is generated into a separate manifest-backed `/steamshine/` asset tree and routes for setup, login, dashboard, pairing, clients, and logs; session cookies are Secure, HttpOnly, and SameSite=Strict, mutations require same-origin CSRF tokens, and sessions are unit-tested for expiry. The migration switches are configuration-validated so both UIs cannot be disabled: a packaged-binary smoke run confirms the default upstream root and confirms that a configuration disabling both UIs restores upstream root (200) while SteamShine remains disabled (404). Chromium verifies the SteamShine root switch with the upstream `/sunshine/` compatibility route. A pinned SteamOS-container run built the binary, installed the Artifact into an isolated HOME, and passed upstream and SteamShine HTTPS smoke checks plus Chromium credential setup, separate SteamShine login, escaped hostile client-name rendering, checked that test credentials/PINs do not appear in the service log, session-cookie attributes, CSP, CSRF/Host/Origin/malformed/oversized request rejection, unauthenticated revoke and static traversal rejection, login/PIN rate limits, credential-change/logout session invalidation, deep-link loading, hydration, and invalid-PIN validation. Browser-level mocked pairing/client synchronization, full configuration/application migration, approved logo/favicon assets, LAN/SteamOS hardware acceptance, and streaming-time performance acceptance remain required. See `docs/WEB_UI_COEXISTENCE_AND_VALIDATION_PLAN.md`. |
