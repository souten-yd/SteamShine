| Desktop source selection and green-screen recovery | Local service startup tested; Moonlight revalidation pending | In automatic mode, a connected physical output with verified KWin ScreenCast takes precedence, with XDG Portal as the secondary compositor path, even when DRM reports its CRTC disabled. On the local SteamOS host, Portal `Start` stopped responding; the request now has a finite deadline and is explicitly closed, while the automatic path selected DP-1 (3440x1440) through direct KWin ScreenCast and discovered H.264, HEVC, and AV1 Vulkan encoders on the RX 9070 XT without restarting Steam. Automatic monitorless startup does not probe Portal or open a chooser; it falls back directly to a compatible retained or newly owned virtual desktop, where the commandless Desktop entry launches the non-singleton configured Plasma folder surface. Startup fallback frames are explicitly black in Linux system-memory paths; VAAPI and CUDA use initialized black textures, and the active Vulkan Video path runs the normal colorspace shader against a dedicated initialized one-pixel black source instead of returning an uninitialized encoder frame. Pure policy, black-frame, lifecycle, Artifact identity, and systemd startup checks pass; Moonlight visual confirmation is still required from the latest CI Artifact. |
| Gamescope input isolation | Locally built and unit tested; hardware revalidation pending | SteamShine resolves the selected Gamescope `gamescope-*-ei` socket only when its inode is held by the verified PID, it remains inside the trusted current-user runtime, and it is a current-user UNIX socket. A dynamically loaded libei sender routes mouse, keyboard, scroll, and touch/pen pointer emulation to that source. If Game Mode is selected and EIS cannot be verified, input fails closed instead of operating the physical Desktop. The dashboard and session JSON expose `input_route_target` plus the stable `input_route_error`. Disconnect releases the combined touch/pen pointer hold, and EIS capability negotiation never waits on the event hot path. Key translation, shared-pointer release, queue classification, and endpoint-selection tests pass; live Game Mode input is required from the PR 7 artifact. |
| Bounded input/video/network latency pipeline | Locally tested; hardware revalidation pending | Input uses one bounded edge-preserving worker queue with motion coalescing. Capture and encoder queues retain the newest work at fixed bounds, while the ordered network queue applies bounded producer backpressure. Fixed-memory latency rings and counters are aggregated for Web status at most every 500 ms and written once as JSON when the final stream ends. A real 1 kHz, 60-second producer test with a slow consumer passed in 60,008 ms with queue bound 64, preserved key edges, and recovery below 100 ms. |
| IDR reason and recovery accounting | Locally tested; hardware revalidation pending | Client, recovery, periodic, and reconnect IDR reasons are counted separately. Duplicate client requests are limited to one per 250 ms, while recovery and reconnect requests are never delayed. Unit tests cover queue counters, reason classification, and the rate-limit boundary. |
| Visual input latency test application | Locally built and packaged | `steamshine-input-visualizer` provides a fullscreen event-driven color transition with monotonic timestamp, sequence, and frame counters plus Linux joystick activity. `--self-test` passes without a display. It performs no per-event disk writes, is linked into the user-local `bin` directory, and appears as the `Input Latency Visualizer` Moonlight application so the same probe can run inside the selected physical Desktop, owned virtual Desktop, or verified Game Mode session. |
| SteamOS virtual display lifecycle | CI Tested | Feature flag, normalized request, dynamically validated Gamescope command, runtime path confinement to `XDG_RUNTIME_DIR` for launch and orphan recovery, ownership-marked runtime/process cleanup including startup orphan recovery, recorded Gamescope leader PID, app Wayland environment, GameStream launch hook, capture-frame evidence, and capture-loss transition are covered by the focused CI workflow. Monitorless Moonlight validation remains required. |
| Gamescope/PipeWire same-GPU capture | Hardware Tested; current branch revalidation | SteamShine discovers a Gamescope `Video/Source` node through the host PipeWire registry, joins it to its current-user client PID/UID, and attaches a DMA-BUF consumer for Vulkan Video encoding. PCI BDF, card node, and render node are resolved from sysfs; ambiguous GPU selectors are rejected. The RX 9070 XT baseline produced positive frame, packet, byte, and IDR counters. The current branch additionally handles Gamescope nodes without render metadata and capability-restricted `/proc/<pid>/exe`; its Moonlight acceptance is intentionally still pending. |
